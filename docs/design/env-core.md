# Environment config core

Status: **implemented** (TEC-1092, ported by hand from the boilerplate's env core: `5478a7d`, `c33cb26`, `46ab039`, `85ddaec`, `8c5c2c2`, `48c1a22`, `8cd2080`, `b046965`, `ece3989`, `b82338c`, `43a0cb4` and the env part of `24d1b20`). Operator steps: [DEVELOPMENT.md](../DEVELOPMENT.md) → Production / Dokploy → Environment file. Adding a variable: [EXTENDING.md](../EXTENDING.md) → Environment variables.

## 1. Goal

Production env used to live on four hand-maintained surfaces that drifted against each other and against the code: `.env.example` (local dev), a prose `.env.server.example`, `backend/internal/config` (what the backend really reads) and `compose.prod.yml`'s `x-backend-environment` (what reaches the containers). Operators copied `.env.example` to `.env.server` and replaced about fifteen secrets by hand, and several backend knobs (`JWT_*_TTL`, `DB_MAX_CONNS`, `STORAGE_MAX_BYTES`, `BULK_*`, `HTTP_*_TIMEOUT`, `CENTRIFUGO_TOKEN_TTL`) were read by `config.go` but never delivered, so values set in Dokploy were silently ignored.

Now one versioned schema, `deploy/env/schema`, drives:

- the production file (`scripts/prod-env.sh init`, asks only for `APP_URL`),
- the committed `.env.server.example` (`scripts/prod-env.sh example`),
- CI checks that the schema, `.env.example`, the backend's env reads and `compose.prod.yml` agree,
- the backend boot guard (`guardedSecrets`), through a Go test.

Local development is unchanged: `cp .env.example .env && make local-dev`, no generator.

Out of scope: secrets in git (SOPS/age), direnv, a typed loader rewrite of `config.go`. The frontend container's `process.env.*` reads are not checked by the compose-env check (see §8).

## 2. Schema format

`deploy/env/schema` is line-oriented. `##` lines are schema-only notes; `#` lines and blank lines are copied into the generated files, so the schema documents itself for operators.

One managed key per line, `KEY | rule`:

| Rule | Meaning |
|---|---|
| `ask:<default>` | Prompt the operator (or `--set KEY=…`). `<default>` is a template; `--yes` accepts it. A default that names a missing key resolves to empty, which is how `APP_URL | ask:{AUTH_URL}` upgrades a hand-made file. |
| `derive:<template>` | Computed. `{KEY}` = any earlier key, plus `{APP_HOST}`, `{APP_SCHEME}`, `{APP_LABEL}` from `APP_URL`. |
| `const:<value>` | Written once (`DB_USER=app`, `SMTP_PORT=587`, `BILLING_RENEWAL_ENABLED=false`); the operator may edit it. |
| `secret:hex\|b64\|alnum:<n>` | Generated by openssl (`hex`/`b64`: n bytes, `alnum`: n chars) once and kept forever. |
| `vapid:public` / `vapid:private` | One P-256 Web Push key pair (base64url, no padding), generated together. |
| `empty` | Managed but blank. Either the operator fills it (`SMTP_*`), or blank keeps the default of `compose.prod.yml` / `config.go` (the "Optional tuning" block). |

Directives:

| Directive | Meaning |
|---|---|
| `@version N` | Current version, stamped as `ENV_SCHEMA_VERSION=N`. Bump it with every change. |
| `@rename OLD NEW <ver>` | `upgrade` moves the existing value (a deployed secret survives the rename). |
| `@remove KEY <ver>` | `upgrade` comments the key out (`# removed@<ver>: KEY=…`), so a rollback can recover it. |
| `@norotate KEY` | `upgrade --rotate` refuses KEY: `APP_ENCRYPTION_KEY` (stored credentials become unreadable) and `DB_PASSWORD` (Postgres keeps it in its volume). |
| `@unmanaged KEY reason` | ComCode addition. The backend reads KEY, but it is not an operator value: `compose.prod.yml` fixes it (`APP_ENV`, `DB_HOST`, `S3_ENDPOINT`, …), it is an alias (`SMTP_FROM`, `S3_PUBLIC_BASE_URL`), or a one-off tool input (`DATABASE_URL`, `LEGACY_EXPORT_*` for `cmd/migrate-legacy`). Never written to `.env.server`. It lets the sync check (§7) require that **every** backend env read is in the schema. |

Compose-only knobs (`COMPOSE_PROJECT_NAME`, `APP_NETWORK_NAME`, `*_VOLUME_NAME`) are not in the schema and keep their compose defaults; `.env.example` documents them.

### What the schema covers (v1)

- **Identity:** `APP_URL` (asked), `NAME_PREFIX` (default: first host label), `IMAGE_REPO` (default `ghcr.io/comcode-app/comcode-app-go`), `IMAGE_TAG` (`main`, or `v0.N` / `sha-<short>` to pin). `compose.prod.yml` builds the image names itself (`${IMAGE_REPO}-backend:${IMAGE_TAG}`, `-frontend:${IMAGE_TAG}`) and pulls them. Schema v2 (TEC-1095) removed the derived `BACKEND_IMAGE` / `FRONTEND_IMAGE` keys (`@remove`): `upgrade` comments them out of a v1 file. `IMAGE_PULL_POLICY` is a compose-only knob (default `always`), not a schema key.
- **Public URLs:** `AUTH_URL`, `PUBLIC_FRONTEND_URL`, `CORS_ALLOWED_ORIGINS`, `CENTRIFUGO_ALLOWED_ORIGINS` (= `APP_URL`), `AUTH_WEBAUTHN_RP_ID` (= host), `CENTRIFUGO_WS_URL` (asked, default `wss://realtime.<host>/connection/websocket`), `NEXT_PUBLIC_CENTRIFUGO_URL`, `STORAGE_PUBLIC_BASE_URL` (asked, default `https://media.<host>/<S3_BUCKET>`, the SeaweedFS media domain).
- **Secrets:** `DB_PASSWORD`, `REDIS_PASSWORD`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `AUTH_SECRET`, `AUTH_ADAPTER_SECRET`, `APP_ENCRYPTION_KEY`, `CENTRIFUGO_API_KEY`, `CENTRIFUGO_TOKEN_HMAC_SECRET`, `MEILI_MASTER_KEY`, the VAPID pair. All alphanumeric/hex/base64, so they survive the SeaweedFS identity heredoc in `compose.prod.yml`.
- **Mail:** `MAIL_FROM` (derived), `MAIL_FROM_NAME`, `SMTP_*`.
- **Billing:** `BILLING_RENEWAL_ENABLED` (`false` until the operator opts in), `BILLING_RETRY_DAYS`, `BILLING_GRACE_DAYS`. iyzico and PayTR credentials are not env vars: they are stored in the database, encrypted with `APP_ENCRYPTION_KEY`. GeoIP (MaxMind account/licence) and analytics settings are admin-panel settings too.
- **Error tracking / metrics:** `SENTRY_DSN` (Sentry or GlitchTip; fallback while the admin panel has no backend DSN), `SENTRY_ENVIRONMENT`, `SENTRY_RELEASE`, `METRICS_ADDR`.
- **Optional tuning** (blank = default): `APP_NAME`, `TRUSTED_PROXIES`, `LOG_*`, `HTTP_*_TIMEOUT`, `DB_SSLMODE`, `DB_MAX_CONNS`, `JWT_*_TTL`, `CENTRIFUGO_TOKEN_TTL`, `STORAGE_DRIVER`, `STORAGE_MAX_BYTES`, `S3_REGION`, `QUEUE_*`, `BULK_*`, `SEARCH_*`, `MEILI_INDEX_PREFIX`, and the frontend's `API_URL`, `AUTH_TRUST_HOST`, `NEXT_PUBLIC_*` (baked into the bundle at build time).

## 3. Generator — `scripts/prod-env.sh`

bash 4.3+ and openssl, no network. Make targets: `prod-env-init`, `prod-env-upgrade`, `prod-env-check` (`PROD_ENV_FILE`, default `.env.server`; extra flags via `ARGS=`).

- **`init`**: asks `APP_URL` and offers the defaults above, derives every URL, generates every secret, writes `.env.server` with mode 600 and stamps `ENV_SCHEMA_VERSION`. Refuses to overwrite an existing file.
- **`upgrade`**: keeps every existing value verbatim, applies `@rename`/`@remove` in version order, fills only missing (or blank, for non-`empty` rules) keys, re-stamps the version, backs up to `<file>.bak`. Idempotent. `--rotate K1,K2` regenerates named secrets after a confirmation (VAPID as a pair) and refuses `@norotate` keys.
- **`check`**: read-only; exits 1 on a version gap, missing or blank keys, renamed/removed keys still present, an invalid `ask:` value, and secrets still holding their `.env.example` value.
- **`example`**: renders `.env.server.example` (secrets blank, values for `https://app.example.com`, a "generated, do not edit" header). Deterministic.

Secret values are never printed. `.gitignore` ignores `.env.server` and `.env.server.*` (backups and temp files hold live secrets) except `.env.server.example`.

Tests: `scripts/prod-env.test.sh` (init, defaults, image derivation, secret formats, VAPID pair, `docker compose config` on the generated file, check findings, rename/remove upgrade, idempotency, rotation, a legacy `.env.example`-shaped file, schema validation including `@unmanaged`).

## 4. Runtime guard

`backend/internal/config/guard.go` (TEC-1100) validates `APP_ENV` and refuses, outside development/test, every secret in `guardedSecrets` that is empty, a public default or shorter than its minimum. `backend/internal/config/schema_test.go` ties it to the schema:

- every `secret:`/`vapid:` key of the schema has a `guardedSecrets` row, or an entry in `unguardedSchemaSecrets` with a reason (`AUTH_SECRET`: frontend only; the VAPID pair: public / no development default);
- every row is a `secret:` key of the schema;
- the length `prod-env.sh` generates for each row's key meets its `MinLen`, so a fresh `init` always boots.

## 5. Generated `.env.server.example`

Committed, and always `scripts/prod-env.sh example` output. Fix drift with `scripts/prod-env.sh example > .env.server.example`.

## 6. Local defaults

`.env.example` stays hand-written. The sync check requires every managed schema key to have a line there, so a production key always has a local default.

## 7. Sync check — `scripts/check-env-sync.sh`

`make env-check` runs it after the compose-env check. It fails when:

1. `.env.server.example` differs from `prod-env.sh example`;
2. a managed schema key has no line in `.env.example`;
3. the backend reads an env var (string-literal `getEnv`/`getInt`/`getInt64`/`getBool`/`getDuration`/`getFloat`/`os.Getenv`/`os.LookupEnv` in non-test Go files under `backend/`) that is neither a managed key nor `@unmanaged`, or an `@unmanaged` key is no longer read;
4. a `deploy/env/compose-env.allow` key is not `@unmanaged` (a key the containers never receive cannot be an operator value);
5. `scripts/prod-env.test.sh` fails.

Dynamic key names are not detected; keep reads literal.

## 8. compose-env check — `scripts/check-compose-env.sh`

Every env var the backend reads must reach the `backend` and `worker` containers, or carry a decision in `deploy/env/compose-env.allow` (`KEY | omit|wire | reason`).

- **Delivered set:** each service's environment from `docker compose config`, resolved with an env that `prod-env.sh init` generates. That is what the container receives (anchors and merges applied). It needs the docker compose CLI, not a daemon. As a side effect it fails if compose starts requiring a variable the schema does not manage.
- **`omit`:** `S3_PUBLIC_BASE_URL` (alias), `STORAGE_LOCAL_PATH` (local driver), `CENTRIFUGO_ENABLED`, `REDIS_DB`, `MAIL_DRIVER` (only smtp exists), `SMTP_FROM` (alias), `DATABASE_URL` (the migrate service has its own DSN), `LEGACY_EXPORT_URL` / `LEGACY_EXPORT_TOKEN` (inputs of `cmd/migrate-legacy`, passed at exec time).
- **`wire`:** should be delivered but is not yet; a warning with a behaviour-neutral `KEY: ${KEY:-}` snippet. Empty today: the operator tunables are wired in `x-backend-environment` as `KEY: ${KEY:-}`, so an unset value lets `config.go` apply its default (`43a0cb4`).
- Fails on an undelivered read without a decision, stale entries (no longer read, or `omit` but delivered), a service with no environment, a malformed allowlist. Tests: `scripts/check-compose-env.test.sh`.

The frontend container is not covered: its reads (`process.env.*`, `NEXT_PUBLIC_*` inlined at build time) need a different extractor. The frontend keys it uses in production are in the schema by hand.

## 9. CI

The `env` job in `.github/workflows/ci.yml` runs `scripts/check-env-sync.sh`, `scripts/check-compose-env.sh` and `scripts/check-compose-env.test.sh`, and is part of the `ci` gate. The `changes` job sets its `env` output for `deploy/env/**`, `compose*.yml`, `.env.example`, `.env.server.example`, `Makefile`, the env scripts, `backend/internal/config/**`, and any backend Go diff line that adds or removes an env read; a push to `main`, a manual run or a `ci.yml` change run it too.
